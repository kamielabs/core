# PR - RC Setup & Test Infrastructure

## Overview

This PR finalizes the runtime architecture before the first RC validation cycle.

The focus is not feature expansion but runtime stabilization, parser cleanup, event consistency, help system completion, test infrastructure setup and preparation of the official v0.1 TEST_PLAN.

This PR establishes the final validation baseline that will be used before tagging the first Release Candidate.

---

## Runtime & Events

### RFC-0004 Implemented

Implemented:

* RFC-0004-parserissues-to-events-migration.md

Parser issues are now fully integrated into the events architecture.

This removes the previous ParserIssues system and allows all runtime diagnostics to follow the same event lifecycle.

### EventsManager Review

Reviewed and updated:

* EventsManager
* emit methods
* terminal event handling
* runtime event propagation

This work simplifies the runtime flow and prepares future runtime extensions.

### Event Naming Convention Update

Updated all runtime event names:

```txt
OLD_EVENT_NAME
```

↓

```txt
event.name
```

This change prepares the future static i18n system while improving naming consistency across the runtime.

### Locales Update

Updated all builtin locale messages to reflect the new event naming convention.

---

## Parser

### Parser Fixes

Fixed multiple parser-related issues discovered during runtime validation.

### Builtin Module Binding Fix

Fixed an issue where builtin module/global bindings could bypass expected parser flows.

A temporary hardcoded resolution strategy has been introduced.

A smarter parser phase picker will be implemented in a future version.

### Flags Validation Review

Reviewed current flag management behavior.

Additional validation improvements were identified and documented separately in:

```txt
known_issues/0001-Parser-Flags-Hardening.md
```

These improvements are not required for v0.1 validation.
