## I18n Runtime Rework

This update restructures the i18n runtime validation layer and strengthens runtime invariants between:

* events
* translations
* runtime names
* developer-facing keys

The goal is to guarantee deterministic runtime behavior while preserving flexible custom i18n usage.

---

## Added

### Runtime name invariant helpers

Added canonical runtime name helpers to normalize and validate:

* builtin runtime names
* custom runtime names

Rules:

* builtins:

  * key: `runtimeReady`
  * name: `CORE_RUNTIME_READY`
* customs:

  * key: `testEventCustom1`
  * name: `TEST_EVENT_CUSTOM1`

---

### Strict builtin runtime validation

Builtin message events are now validated against english builtin translations during i18n resolution.

The core now guarantees:

* every builtin message event exists in english
* unknown builtin runtime names are rejected
* builtin translations remain deterministic

---

### Translation key/runtime-name validation

Added strict validation for:

* builtin translations
* custom translations

The builder now validates:

* key ↔ runtime name consistency
* reserved namespace usage
* invalid runtime naming patterns

---

### Reserved namespace protection

Added strict validation preventing custom runtime names from using:

* `CORE_*`

This now applies consistently to:

* events
* translations

---

### Silent builtin language fallback

Builtin messages now fallback silently to:

* english (`en`)

No warnings are emitted when:

* the requested language does not exist for builtins

---

### Custom runtime fallback warnings

Custom translations:

* do not fallback to another language
* fallback directly to runtime name

Warnings are now configurable through:

* `skipI18nWarnings`

---

## Changed

### Runtime i18n facts simplification

`RuntimeI18nFacts` has been simplified.

Translation indexes remain internal to the `I18nManager`.

Only the resolved runtime language is exposed publicly.

---

### I18n validation scope

Builtin validation now only applies to:

* builtin translation dictionaries

Custom-only languages are ignored by builtin validation logic.

---

### Runtime translation resolution

`I18nManager.tr()` behavior has been updated:

* builtins:

  * strict english fallback
  * fatal if missing

* customs:

  * runtime-name fallback
  * optional warning emission

---

## Internal

### Translation indexes

Added:

* `byKey`
* `byName`
* `byLang`

indexes for runtime translation resolution.

---

### Runtime invariant hardening

Improved runtime consistency between:

* events
* translations
* runtime names
* builder validation
* i18n resolution

---

## Notes

This update intentionally keeps:

* builtin/custom translations merged internally

A future update may fully separate builtin and custom translation registries internally now that runtime invariants are stabilized.
