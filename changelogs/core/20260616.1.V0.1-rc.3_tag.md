# 20260616.1.v0.1-rc.3_tag

## Summary

This Release Candidate introduces path resolution support and fixes stage resolution ordering issues discovered during RC validation.

The main objective of this RC is to stabilize stage configuration loading before the final v0.1.0 release.

---

## Added

### Path Resolution

Added support for Linux-like path expansion in core path resolution helpers.

Supported syntax:

```txt
~
$VAR
${VAR}
```

Examples:

```txt
~/.config/core/config.env
$HOME/.config/core/config.env
${HOME}/.config/core/config.env
```

All supported forms resolve correctly before filesystem access.

### Environment Variable Expansion

Added environment variable expansion support for path-based configuration values.

Supported forms:

```txt
$VAR
${VAR}
```

Resolution can operate in strict or non-strict mode depending on runtime requirements.

---

## Fixed

### Default Stage Resolution

Fixed builtin default stage file resolution.

Previously, builtin stage file overrides could be applied after env file loading, resulting in incorrect configuration loading order.

The runtime now resolves the effective stage file before env file loading.

### Stage Override Precedence

Validated and enforced the following precedence order:

```txt
builtin defaults
↓
runtime defaults
↓
env file values
↓
environment variables
```

This order now behaves consistently for both builtin and custom stages.

### Runtime Path Handling

Resolved path expansion and normalization issues affecting stage file loading when using:

```txt
~
$HOME
${HOME}
```

