# 🧾 PR — Events system rework (v0.1 finalization)

## 🚀 Overview

Full cleanup and stabilization of the Events system for v0.1.

This PR finalizes:

* deterministic event flow
* sync terminal events (fatal/error)
* clean separation between internal and external APIs
* improved developer-facing tools API
* full type system revision for events

---

## 🧠 Key design decisions

### 1. Event identifier rename

```ts
event.code → event.name
```

* removes ambiguity with future numeric codes
* aligns with event identity usage across the core
* prepares for future introduction of structured `code` (e.g. `F00001`)

---

### 2. Full type system rewrite

* all event types have been reviewed from scratch
* strict typing enforced across:

  * kind (signal/message)
  * level (trace → fatal)
  * phase
* improved generics consistency across the EventsManager

👉 result: safer and more predictable event usage

---

### 3. Builtins re-aligned

* all builtin events have been reviewed and updated
* ensured full consistency with:

  * new `event.name`
  * updated type system
  * event levels and phases

---

### 4. Removal of temporary/internal APIs

* removed all temporary methods used during previous iterations
* removed `internalEmit`
* cleaned up transitional logic

👉 EventsManager is now stable and minimal

---

### 5. Terminal events are now synchronous

* `throw()` methods return `never`
* fatal/error events trigger immediate process termination
* no async continuation after terminal events

👉 ensures deterministic behavior

---

### 6. Internal API simplified

```ts
emit()   // trace, debug, info
warn()   // warning
throw()  // error, fatal
```

* clear responsibility per level
* simplified control flow

---

### 7. External API (EventsManager)

```ts
signalTrace / signalDebug / signalInfo / signalWarn / signalThrow
messageTrace / messageDebug / ...
```

* explicit separation signal / message
* consistent naming
* no leakage of internal logic

---

### 8. Developer API (`tools`)

```ts
tools.signal.trace(...)
tools.signal.throw(...)
tools.message.info(...)
```

* clean and predictable DX
* strongly typed
* aligned with runtime behavior

---

### 9. Deterministic execution model

* all dispatch is awaited internally
* terminal events stop execution deterministically
* no uncontrolled async behavior

---

### 10. Codebase cleanup

* simplified dict initialization logic
* removed redundant guards (`return` after throw)
* reduced unnecessary async complexity
* improved readability and maintainability

---

### 11. Correct Flow listeners vs Output listeners (system/runtime)

* Refactored listener types to enforce a strict separation between:
  * **Flow listeners** (internal orchestration)
  * **Output listeners** (system/runtime outputs)

* Introduced distinct types:
  * `EventFlowListener`
  * `EventOutputListener`

* Flow listeners:
  * no longer support the `channel` property
  * are strictly used for internal flow handling
  * cannot interact with output routing

* Output listeners:
  * support the optional `channel` property
  * are used for system/runtime output dispatching

* Updated internal helpers to propagate this separation consistently
  (generic typing across registration, removal, and resolution)

* This prevents accidental mixing of flow logic and output routing
  and strengthens type safety across the event system

---

### 12. AGENT.md - Agent Integration (workflow & usage)

* Introduced an agent-assisted workflow for development tasks
* The agent is currently used for:
  * code auditing and consistency checks
  * JSDoc generation and normalization
  * translations (FR/EN)
  * structural validation after manual changes

* The agent is **not used to write or modify core logic directly**

* Defined workflow:
  1. Agent performs audit / review
  2. Agent suggests corrections or improvements
  3. Developer reviews and applies changes manually
  4. Agent re-validates and performs a final consistency check

* All decisions remain developer-driven; the agent is strictly an assistant

* Global behavior and constraints are defined in `AGENT.md`

* terminal events guarantee full dispatch before exit
* no reliance on async side-effects after fatal/error
